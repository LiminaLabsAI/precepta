## Bugs

| ID | Title | Priority | Status | Phase | Detail |
|----|-------|----------|--------|-------|--------|
| BUG-001 | Model Plane: adding a 2nd backend of the same provider **type** overwrites the first | P2 | **resolved 2026-08-01** | 10 | Backends are keyed by provider *type*, not per-model. Console sends `provider=PROVIDER_OF[type]` (e.g. every HF backend → `"hf"`); `registered_backends.provider` is PK with `ON CONFLICT DO UPDATE`, and `registry[provider]=backend`, so a 2nd HF (or vLLM/Ollama) model **replaces** the first. The typed **Name** is sent but ignored. Fix: give each backend a unique id (slug of Name, or provider+name) and key the registry/store/pricing/routing/sensitive-approved/key-scopes by that id. Ripples through anything that references a backend by name — do as a small scoped change. Reported by user 2026-08-01. |
| BUG-002 | Data plane: malformed chat request (missing/empty `messages`) returned **502** instead of **400** | P2 | **resolved 2026-08-12** | 15 | `POST /v1/chat/completions` (and its `/v1/inference` alias) forwarded an empty/invalid body to the backend, which 400'd, and the gateway surfaced it as `502 backend_unavailable` — breaking OpenAI-compat (a client error must be a `400 invalid_request_error`). Found during full live API auth/contract verification. Fix: validate the request shape up front — non-object body or missing/empty `messages` → `400 invalid_request_error` before any routing/inference. `+test_chat_missing_messages_is_400_not_502`. Embeddings/moderations already validated correctly. |
| BUG-003 | Cache never engaged unless caller sent `temperature:0` explicitly | P2 | **resolved 2026-08-12** | 15 | `cache.is_cacheable` required `temperature == 0`, but the Playground (and most OpenAI clients) omit `temperature` — so `kw.get("temperature")` was `None`, `None == 0` is False, and the response cache never engaged even with caching toggled **on**. Fix: treat an **unset** temperature as deterministic/cacheable (`temp is None or temp == 0`); an explicit `temperature > 0` still opts out. Also surfaced cache status in the response envelope (`precepta.cache` = `hit`/`miss`/`skipped`) so operators can see it working. Compression verified working as-designed (smart mode skips <400-char prompts; baseline/aggressive engage on longer input). Found when user reported cache/compression not working when on. +tests. |
